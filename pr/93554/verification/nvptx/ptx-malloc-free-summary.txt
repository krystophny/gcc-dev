Reading the result:
- The three baseline tests emit malloc/free for every parallelism
  variant, but the guard (if priv.data != 0B) is always false at
  runtime because the allocatable component stays null throughout
  the region; the call is compiled but never executed.
- pr93554-2 allocates the component inside the loop body and never
  deallocates, so the per-thread finaliser's free runs at region
  exit on every thread (malloc=2 is the user-facing allocate plus a
  descriptor helper).
- pr93554-3 carries a whole allocatable through num_gangs(4) gang
  partitioning; the OpenACC runtime allocates the per-gang copy on
  entry and frees it on exit.  Malloc/free = 1/1 per entry.
