Supersedes attachment 64103.

Mikael was right that the earlier resolve_charlen-based approach was fixing
this too late and at the wrong level.

The attached patch instead cleans up the declaration-local gfc_charlen nodes in
decl.cc when the parameter-array declaration is rejected.  In this path we
clear the surviving owners first and then drop only the charlens created by
that rejected declaration, so resolve_charlen never sees the stale
character(n) / character(n+1) nodes later.

This avoids both the original invalid-memory access and the later stray
"Scalar INTEGER expression expected" diagnostic, without adding namespace-tree
walks to charlen resolution.
